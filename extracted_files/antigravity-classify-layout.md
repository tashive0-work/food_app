# 작업 A. classify() 진단 분기 재설계

## 배경 — 현재 무엇이 잘못되었는가

`classify()`는 6축 상태값을 받아 진단 문구를 반환합니다. 현재 분기 순서에 논리적 결함이 있어, **추천 결과와 진단 문구가 서로 모순되는 케이스가 발생**합니다.

**실제 발생 사례:**

사용자 상태가 `허기 1 / 기력 4 / 자극 4 / 위로 1 / 여유 1 / 온기 4` 일 때
- 추천 1위: 라면, 2위: 마라탕 (자극적이고 뜨거운 음식)
- 진단 문구: **"가볍게 끝내고 싶은 상태 — 많이는 안 당기시죠"**

자극이 최대치(4/4)인 사용자에게 "많이는 안 당기시죠"라고 말하면서 마라탕을 추천하고 있습니다.

**원인:** `hunger <= 1` 조건이 6번째 분기에 있어, 허기만 낮으면 다른 축 값과 무관하게 여기서 걸립니다. 자극·온기가 아무리 높아도 무시됩니다.

**추가 문제:** 전체 15,625가지(5^6) 상태 조합을 분석한 결과, `자극 4` 상태를 위한 전용 분기가 없고, `온기 0~1`(시원한 것을 원하는 상태)을 위한 분기도 없습니다. 결과적으로 12.4%가 "무난하게"라는 무의미한 기본값으로 떨어집니다.

## 수정 내용

**파일:** `src/lib/recommend.ts`

`classify` 함수 **전체**를 아래로 교체해 주세요.

```ts
export function classify(s: AppState): Verdict {
  const { hunger, energy, spice, comfort, time, warm } = s;

  // 1순위: 몸 상태가 안 좋을 때 (기력 낮음 + 자극 원하지 않음)
  // 다른 어떤 조건보다 우선함 — 컨디션이 나쁜 사용자를 최우선 보호
  if (energy <= 1 && spice <= 1)
    return {
      title: "속을 달래야 하는 상태",
      line: "몸이 자극을 원하지 않아요. 부담 없이 넘어가는 것들만 추렸어요.",
    };

  // 2순위: 시간이 없는데 배가 고픔
  if (time <= 1 && hunger >= 3)
    return {
      title: "당장 채워야 하는 상태",
      line: "고민할 여유가 없어요. 빨리 나오고 확실히 배부른 쪽으로 골랐어요.",
    };

  // 3순위: 힘든 하루 + 매운 것을 원함
  if (comfort >= 3 && spice >= 3)
    return {
      title: "매콤한 위로가 필요한 상태",
      line: "오늘 좀 힘드셨네요. 얼큰하게 한번 풀어내는 메뉴로 모았어요.",
    };

  // 4순위: 자극 최대치 — 신규 분기
  // 위로 수치와 무관하게 입이 확실히 자극을 원하는 상태
  if (spice >= 4)
    return {
      title: "얼큰한 게 당기는 상태",
      line: "입이 확실히 자극을 원하네요. 화끈한 쪽으로 골랐어요.",
    };

  // 5순위: 위로가 필요함
  if (comfort >= 3)
    return {
      title: "따뜻한 게 필요한 상태",
      line: "맛보다 위로가 먼저인 날이에요. 익숙하고 포근한 메뉴 위주예요.",
    };

  // 6순위: 배고프고 기력도 있음
  if (hunger >= 3 && energy >= 3)
    return {
      title: "제대로 먹어야 하는 상태",
      line: "몸도 입도 준비됐네요. 든든하게 채우는 쪽으로 골랐어요.",
    };

  // 7순위: 가볍게 — 자극을 원하지 않을 때만 해당 (조건 강화)
  if (hunger <= 1 && spice <= 2)
    return {
      title: "가볍게 끝내고 싶은 상태",
      line: "많이는 안 당기시죠. 가볍게 마무리하기 좋은 것들이에요.",
    };

  // 8순위: 시간과 기력이 모두 여유로움
  if (time >= 3 && energy >= 3)
    return {
      title: "천천히 즐기고 싶은 상태",
      line: "시간도 기력도 있어요. 손이 조금 가도 아깝지 않은 메뉴예요.",
    };

  // 9순위: 시원한 것을 원함 — 신규 분기
  if (warm <= 1)
    return {
      title: "시원한 게 당기는 상태",
      line: "뜨거운 건 오늘 아니에요. 시원하게 넘어가는 것들로 모았어요.",
    };

  return {
    title: "무난하게 잘 먹고 싶은 상태",
    line: "특별히 튀는 곳 없이 균형 잡힌 하루네요. 실패 없는 쪽으로 모았어요.",
  };
}
```

## 변경 요약

| 변경 | 내용 |
|---|---|
| 순서 변경 | `energy<=1 && spice<=1`(속 달래기)을 최상단으로 이동 |
| 조건 강화 | `hunger<=1` → `hunger<=1 && spice<=2` |
| 신규 분기 | `spice>=4` → "얼큰한 게 당기는 상태" |
| 신규 분기 | `warm<=1` → "시원한 게 당기는 상태" |
| 구조조명 | `warm`을 구조분해 대상에 추가 |

**중요:** 함수 시그니처의 구조분해에 `warm`이 추가되었습니다. 기존에는 `const { hunger, energy, spice, comfort, time } = s;` 였으나 `warm`이 필요하므로 반드시 포함해야 합니다.

## 검증

전체 15,625가지 상태 조합에 대해 사전 시뮬레이션을 완료했으며, 결과는 다음과 같아야 합니다.

- `자극 >= 3` 이면서 "가볍게 끝내고 싶은 상태"로 분류되는 케이스: **0건**
- "무난하게" 기본값으로 떨어지는 비율: 12.4% → **8.9%**

**필수 확인 케이스:**

1. `허기1 기력4 자극4 위로1 여유1 온기4` → **"얼큰한 게 당기는 상태"**
2. `허기3 기력0 자극0 위로4 여유2 온기3` → **"속을 달래야 하는 상태"**
3. `허기2 기력2 자극2 위로2 여유2 온기0` → **"시원한 게 당기는 상태"**

`npm run dev` 실행 후 실제 진단을 진행하여 영수증에 표시되는 진단명이 위와 일치하는지 확인해 주세요.

# 작업 B. 데스크톱 레이아웃 개선

## 배경

현재 `max-width: 720px` 고정이라 1920px 데스크톱에서 화면 양옆이 전부 빈 배경으로 남습니다. 추천 카드 30개가 1열로만 나열되어 스크롤이 과도하게 길어집니다.

## 수정 내용

**파일:** `src/app/globals.css`

파일 하단의 `@media (min-width:768px)` 블록을 찾아 아래로 **교체**해 주세요.

**현재:**
```css
@media (min-width:768px){
  .hero{padding:24px 22px 20px;}
}
```

**교체 후:**
```css
@media (min-width:768px){
  /* 히어로 — 중앙 정렬로 데스크톱 균형 확보 */
  .hero{padding:40px 22px 34px;}
  .heroInner{max-width:900px;text-align:center;}
  .hero .sub{max-width:none;margin-left:auto;margin-right:auto;}

  /* 콘텐츠 폭 확대 */
  .wrap{max-width:900px;padding:32px 22px 60px;}
  .tabs{max-width:900px;}

  /* 추천 카드 2열 그리드 */
  .grid{
    display:grid;
    grid-template-columns:repeat(2, 1fr);
    gap:10px;
    align-items:stretch;
  }
  .card{
    flex-direction:column;
    align-items:flex-start;
    gap:14px;
  }
  .cardTop{width:100%;}
  .card > div:last-child{width:100%;justify-content:space-between;}

  /* 영수증은 지나치게 넓어지지 않도록 제한 */
  .receipt{max-width:520px;margin:0 auto;}

  /* 진단 질문 영역도 중앙 정렬 */
  .quiz{max-width:640px;margin:0 auto;}
}

@media (min-width:1200px){
  /* 큰 화면에서 3열 */
  .grid{grid-template-columns:repeat(3, 1fr);}
  .wrap{max-width:1100px;}
  .tabs{max-width:1100px;}
  .heroInner{max-width:1100px;}
}
```

## 주의사항

- 기존 `@media (max-width:400px)` 블록과 `@media (prefers-reduced-motion:reduce)` 블록은 **수정하지 말고 그대로 둘 것**
- `.receipt`에 `max-width`를 주는 이유: 영수증 은유상 지나치게 넓으면 어색하므로 의도적으로 제한
- 2열 그리드에서 카드 내부가 세로 배치로 바뀌므로 `flex-direction: column` 필요

## 검증

브라우저 창 폭을 조절하며 확인:

1. **375px (모바일)** — 기존과 동일하게 1열, 레이아웃 깨짐 없음
2. **768px (태블릿)** — 카드 2열, 영수증 중앙 정렬
3. **1440px (데스크톱)** — 카드 3열, 히어로 중앙 정렬, 양옆 공백 감소

특히 **모바일에서 회귀가 없는지** 반드시 확인해 주세요. 미디어쿼리 안에만 작성했으므로 모바일에는 영향이 없어야 정상입니다.
